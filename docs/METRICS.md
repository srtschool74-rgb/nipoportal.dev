# Metric Dictionary (Single Source of Truth Specification)

**Generated:** 2026-11-25  
**Scope:** Admin, Teacher, and Parent Portals, PDF Exports, Excel Exports, Notification Badges, Transport, Attendance, Exams, Report Cards  
**Note:** In `prisma/schema.prisma`, `Student`, `Teacher`, `Parent`, `Class`, `Subject`, `Staff`, and `Bus` use `isActive: Boolean` (plus `Student.enrollmentStatus`, `User.status`, `Message.isDeleted`, `Notification.isRead`, and `Notification.readAt`). There is no `deletedAt` column or `AcademicYear` model (`AcademicBatch` represents batches/academic years).

| **Marks, Exam Totals, % & Grades** | Server-recomputed from all subject entries for that exam (`Absent` included in `maxTotal` with `score = 0` and `isFail = true`). ## 3. Caching & Freshness Rules (To Be Enforced in Task 3)
1. **Single Backend Stats Layer (`backend/services/stats/`)**: Every dashboard card, list header, export summary, PDF summary, and chart series reads from this single module using SQL aggregates (`prisma.$transaction`, `count`, `groupBy`, `aggregate`).
2. **Short TTL + Mandatory Invalidation**: Per-user caches MUST never live in unkeyed shared memory; any server cache uses explicit mutation invalidation (`revalidateTag` / `revalidatePath` + explicit invalidator helpers on every Student, Parent, Teacher, Class, Subject, Attendance, Bus, Exam, Mark, ReportCard, Notification, and Calendar mutation).
3. **Pagination Parity**: Every list query computes `{ items, total, page, pageSize }` where `total` uses the exact same `where` clause as `items`, and summary KPI totals come from `stats/` unpaginated aggregates.
4. **Loading States**: UI pages and client fetch states must use skeleton components (`DashboardSectionSkeleton` / `ResultsSkeleton`) instead of flashing `"0"` while data loads.
